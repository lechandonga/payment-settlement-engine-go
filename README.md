# 支付清算与对账核心（本地模拟）

纯 Go 标准库实现的本地支付清算/结算/对账核心，覆盖「交易受理 → 日终清算 → 结算单对账」整条链路。
不连接任何外部支付网关、银行或真实凭据；金额一律使用最小货币单位（如人民币分）的 `int64`，全程无浮点。
`go.mod` 的 module 声明与 Go 版本保持不变，无第三方依赖。

## 目录结构

| 路径 | 职责 |
| --- | --- |
| `internal/ledger` | 复式记账内核：账户、借贷分录、余额、事务性入账、快照 |
| `internal/payment` | 交易受理：手续费计算、外部请求号幂等、并发重放串行化 |
| `internal/settlement` | 周期清算：批次并发去重、商户部分失败、单独重试 |
| `internal/reconcile` | 结算单 CSV 导入、差异分类、可追溯调账 |
| `internal/engine` | 组装各服务、JSON 文件持久化（原子写）、一致性自检 |
| `cmd/demo` | 本地手工入口，一条命令跑完四个场景 |

## 账本与分录模型

- 账户分三类：`ASSET`（资产，如待清算收单款、结算出款资金、对账差异待查）、`LIABILITY`（每商户一个应付款账户 `M_PAYABLE:<商户号>`）、`INCOME`（手续费收入）。
- 每条 `Entry` 属于一个业务 `TxID`，有借/贷金额（最小单位）。同一 `TxID` 内借方合计必须等于贷方合计，否则整组拒绝入账，不产生半成品分录。
- 余额恒等式：全账本 `Σ借方 == Σ贷方`；单账户余额 = 该账户所有分录的 `借-贷` 之和。负债/收入类账户不允许出现借方余额（防止重复结算导致透支）。
- 受理一笔 10000 分、费率 0.6%（手续费 60 分）的支付：
  - 借：待清算收单款 `10000`
  - 贷：商户应付款 `9940`
  - 贷：手续费收入 `60`
- 同一 `TxID` 重复入账被账本直接拒绝（`ErrTxAlreadyPosted`），这是业务幂等的底层保险。

## 受理与幂等规则

- 幂等键为 `商户号 + 外部请求号`。
- 重复提交：返回首次结果（同一支付 ID、金额、分录）并标记 `Duplicate=true`，不二次扣款；同请求号但金额不同则明确拒绝（`ErrRequestReplay`）。
- 并发重放：同键请求用进程内互斥串行化，先到者完成首次入账，其余全部拿到首次结果的回放；50 goroutine 并发只产生 1 笔交易（见 `TestConcurrentReplayIdempotent`）。
- 幂等索引随快照持久化，重启后依然只入账一次（见 `TestIdempotencyAcrossReload`、引擎重启测试）。

## 清算结算规则

- 结算周期（如 `2026-10-01`）触发时，把所有已受理未清算交易按商户归集，算 `总额 / 手续费 / 应收净额(=总额-手续费)`。
- 商户清算成功写结算分录：借 `商户应付款(净额)` / 贷 `结算出款资金(净额)`，随后交易标记为已结算。
- 批次并发：同一周期并发触发只生成一份有效批次（批次先登记索引再处理），所有调用收敛到同一批次 ID。
- 部分失败：通道异常（`FailHook` 模拟）或入账失败的商户记为 `FAILED` 并保留原因、尝试次数；不写结算分录、不标记交易。成功商户记为 `SUCCESS`。
- 重跑：再次触发同周期返回同一批次；`SUCCESS` 商户直接跳过，绝不重复出款；`FAILED` 商户可用 `RetryMerchant(批次, 商户)` 单独重试，成功后交易继续推进。
- 持久化：每个关键步骤后 `Save()`，JSON 写临时文件再 `rename` 原子落盘。重启后已完成状态不回退，未完成商户可继续重试。

## 对账差异分类与处理

结算单为本地 CSV，表头 `merchant_id,payment_id,net_amount`（净额，最小单位）。

| 类型 | 含义 | 调账方式（分录均借贷相等，备注含原交易号） |
| --- | --- | --- |
| `MATCHED` | 逐笔一致 | 不调账 |
| `AMOUNT_MISMATCH` | 金额不符 | 差额（结算单-账本）多付/少付部分计入「对账差异待查」科目 |
| `MISSING_LEDGER` | 结算单有、账本无 | 原交易存在则补记商户结算分录；原交易也缺失则差额挂待查 |
| `MISSING_STATEMENT` | 账本有、结算单无 | 冲回多记的结算分录（借记出款资金、贷记商户应付款） |
| `DUPLICATE_STMT` | 结算单内重复记录 | 显式标记上报，以首条为准；账本本就一笔，不重复调账 |

任何一条差异都会出现在报告里，不存在静默忽略；调账幂等（重复执行不产生新分录），调账前后全账本借贷总额各自守恒且始终相等。

## 本地启动与验证

```bash
# 一条命令手工跑完：受理(重复/并发) → 部分失败清算+重试 → 模拟重启 → 对账+调账
go run ./cmd/demo

# 仅从已有状态目录重启，验证状态恢复与守恒
go run ./cmd/demo -restart -dir ./.demo-data

# 用自己的结算单 CSV 对账
go run ./cmd/demo -statement ./my_statement.csv
```

状态文件（`ledger.json` / `payments.json` / `settlement.json`）默认写在 `./.demo-data`，删掉即回到干净状态。

## 测试

```bash
CGO_ENABLED=1 go test -race -v ./...
```

覆盖场景：

- `internal/ledger`：借贷不平拒绝、同 TxID 重复入账拒绝、负债账户透支拒绝、快照恢复。
- `internal/payment`：手续费整数计算与余额勾稽、重复提交返回首次结果且不重复扣款、同键不同载荷拒绝、50 并发重放只入账一次、重启后幂等。
- `internal/settlement`：10 并发触发同一周期只产生一个批次、商户部分失败、重跑不重复结算成功商户、失败商户单独重试成功、快照重启后续做。
- `internal/reconcile`：四类差异全部分类且无遗漏、CSV 解析、调账可追溯到原交易、调账借贷守恒且幂等。
- `internal/engine`：落盘后全新进程从目录恢复，已完成不回退、失败可续做、幂等索引仍生效、多轮重启后一致性自检通过。

`go test -v` 会逐用例打印 `--- PASS/FAIL`；demo 运行日志按「场景 1~4」分段打印每个用例的输入与结果。
