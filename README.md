# payment-settlement-engine-go

本地运行的支付清算与对账核心：模拟商户交易从**受理记账 → 日终清算结算 → 结算单对账 → 差异调整**的完整链路。
全部在本地运行，不连接任何外部支付网关、银行或真实凭据；仅使用 Go 标准库，无第三方依赖。

## 目录结构

```
internal/ledger/     复式记账账本（账户、分录、幂等受理、持久化）
internal/clearing/   按周期的批量清算与结算（批次状态机、失败重试）
internal/reconcile/  结算单对账（差异分类、调整入账）
cmd/pse/             本地演示入口，一次性走完整条链路
```

## 账本与分录模型

- **金额**：一律使用最小货币单位（分）的 `int64`，精确计算，无浮点误差。
- **账户（Account）**：不直接存余额，余额 = 该账户全部分录的 `借方合计 - 贷方合计`，
  因此任意时刻账户余额与分录汇总必然一致。
  - `acct:recv:<商户>` 商户应收户（资产）
  - `acct:pay:<商户>` 商户应付户（负债）
  - `CLEARING` 平台清算过渡户；`ADJUSTMENT` 对账调整过渡户
- **分录（Entry）**：每笔业务生成一借一贷两条等额分录，整个账本任意时刻
  `Σ借方 == Σ贷方`（守恒），`Ledger.Totals()` 可随时校验。
- **交易（Transaction）**：
  - `PAYMENT` 支付：借 商户应收 / 贷 清算过渡户
  - `SETTLEMENT` 结算：借 清算过渡户 / 贷 商户应付户
  - `ADJUSTMENT` 对账调整：借/贷 目标账户，对侧为调整过渡户

### 幂等与并发

- 每笔支付以商户**外部请求号（ExternalID）**为幂等键。
- 重复提交、超时重试、并发重放同一请求号：只入账一次，重复方拿到与首次一致的结果（`Duplicate=true`）。
- 同号但金额/商户不一致：返回 `ErrDuplicate` 明确拒绝，不入账。
- 所有写操作持互斥锁并立即持久化（JSON 临时文件 + 原子 rename），进程重启后状态完整恢复。

## 清算与结算规则

- **批次**：由结算周期（如 `2026-10-02`）唯一确定（`batch-<period>`）。
  同一周期重复或并发触发，最终只产生一份有效批次。
- **清算（归集）**：把账本中 `ACCEPTED` 状态的交易按商户分组，计算各商户应收净额，
  生成 `PENDING` 结算单，交易流转为 `CLEARED`。
- **结算**：按商户逐个执行（默认直接记账本，可通过 `SettleHook` 替换出款通道）：
  - 成功 → `SUCCESS`，交易流转为 `SETTLED`；
  - 失败 → `FAILED` 并记录失败原因，不影响其他商户；
  - 批次全部成功 → `COMPLETED`，否则 `PARTIAL`。
- **重跑与重试**：重跑同周期批次时，`SUCCESS` 的商户跳过不重复结算；
  `FAILED` 商户可用 `RetryMerchant` 单独重试；结算记账本身按 `批次+商户` 幂等。
- **持久化**：批次与结算单状态落盘，重启后已完成的不回退、未完成的可继续推进。

## 对账差异分类与处理

对账以支付交易（`Kind=PAYMENT`）与本地结算单逐笔比对，**每条记录都必须归类，不允许静默忽略**：

| 差异类型 | 含义 | 处理方式 |
|---|---|---|
| `MISSING_IN_STATEMENT` | 账本有、结算单无 | 人工核查（可能为在途/漏单） |
| `MISSING_IN_LEDGER` | 结算单有、账本无 | 自动补记：借 应收户 / 贷 调整户 |
| `AMOUNT_MISMATCH` | 双方都有但金额不符 | 自动补差（多退少补） |
| `DUPLICATE` | 同号在任一侧出现多次 | 人工核查 |

- 调整通过 `Reconciler.Adjust` 入账，`adjustID` 幂等，调整记录以 `ADJ:<原始交易号>` 关联原始交易，全程可追溯。
- 调整分录借贷自动平衡，调整前后账本借贷总额保持守恒。

## 本地启动与验证

```bash
# 走一遍完整链路（受理→清算结算→对账→调整），状态持久化在 ./data
go run ./cmd/pse -dir ./data -period 2026-10-02

# 再跑一遍同周期：观察幂等（重复交易不重复入账、批次不重复结算）
go run ./cmd/pse -dir ./data -period 2026-10-02

# 全部测试（含竞态检测，需要 CGO）
CGO_ENABLED=1 go test -race ./...

# 查看各场景与结果日志
CGO_ENABLED=1 go test -race -v ./...
```

测试覆盖场景（`go test -v` 日志中可见各场景的用例与结果）：

- 重复提交返回一致结果 / 同号冲突明确拒绝
- 并发重放同一请求号只入账一次（64 并发）
- 并发混合记账保持借贷守恒（400 笔）
- 批次并发触发只产生一份有效结算（16 并发）
- 部分商户结算失败 → 重跑不重复结算 → 单独重试成功
- 账本与清算状态重启恢复，已完成不回退、新交易进入下一周期
- 对账四类差异分类、零差异全匹配、调整守恒与可追溯
